# function: capture_posthog

Collects the enabled metadata about the environment running Terraform and attempts to send it to [PostHog](https://posthog.com/) as a `terraform_capture` event. The function always returns `true`, whether the event is sent, skipped, deduplicated, or fails to deliver.

~> **Note:** This function runs local commands and sends network requests while Terraform evaluates it, and it does not guarantee that an event is sent exactly once. Read the [limitations](https://registry.terraform.io/providers/tedilabs/telemetry/latest/docs#limitations) on the provider overview page before using it.

## Example Usage

```terraform
# Configuration using provider functions must include required_providers configuration.
terraform {
  required_providers {
    telemetry = {
      source = "tedilabs/telemetry"
    }
  }
  # Provider functions require Terraform 1.8 and later.
  required_version = ">= 1.8.0"
}

variable "posthog_project_token" {
  type      = string
  sensitive = true
}

check "telemetry" {
  assert {
    condition = provider::telemetry::capture_posthog(
      # connection
      {
        host          = "https://us.i.posthog.com"
        project_token = var.posthog_project_token
      },
      # options: omitted attributes use their defaults.
      {
        network = false
        github  = true
      },
      # extra_data
      {
        module  = "example"
        version = "1.0.0"
      }
    )
    error_message = "Telemetry invocation failed."
  }
}
```

## Arguments

<!-- arguments generated by tfplugindocs -->
1. `connection` (Object, Nullable) PostHog ingestion base URL `host` (for example, `https://us.i.posthog.com`) and `project_token`. A null value skips the capture.
1. `options` (Dynamic, Nullable) Object or map that selects metadata collectors and configures caching, deduplication, pseudonymization, and the event identity. All attributes are optional: the `machine`, `network`, `git`, `github_actions`, `hcp_terraform`, `terraform`, and `toolchain` collectors default to `true`, `github` defaults to `false`, `cache_enabled` and `deduplication_enabled` default to `true`, and `deduplication_keys`, `pseudonymized_keys`, and `identity_keys` default to `[]`. A null value or an unknown attribute, such as a misspelled collector, skips the capture.
1. `extra_data` (Dynamic, Nullable) Additional event properties as an object or map, deep-merged over the collected metadata. Use `{}` when there is nothing to add. A null value is treated as `{}`.

All arguments are positional and required.

<a id="nestedobjatt--connection"></a>
### Nested Schema for `connection`

- `host` (String) PostHog ingestion base URL, such as `https://us.i.posthog.com`, `https://eu.i.posthog.com`,
  or the base URL of a self-hosted instance. The event is sent to the `/i/v0/e/` path under this URL.
  The URL must use `http` or `https`, and must not contain credentials, a query, or a fragment.
  Use `http` only for a local test server: it sends the project token and the event unencrypted.
- `project_token` (String) PostHog project token, sent as the `api_key` of the event.
  Do not use a personal API key. Store the token in a `sensitive` variable.

To disable a call, pass `null` instead of the `connection` object, for example `var.enabled ? var.connection : null`.
Do not wrap the whole call in a conditional expression: Terraform evaluates both of its results, so the function still runs.

<a id="nestedobjatt--options"></a>
### Nested Schema for `options`

`options` accepts an object or a map. All attributes are optional; pass `{}` to use the defaults.
Any other attribute, such as a misspelled collector name, skips the capture,
so that a typo cannot leave a collector enabled by default.

Optional:

- `machine` (Boolean) Whether to collect [`machine`](https://registry.terraform.io/providers/tedilabs/telemetry/latest/docs/guides/collected-metadata#machine) metadata. Defaults to `true`.
- `network` (Boolean) Whether to collect [`network`](https://registry.terraform.io/providers/tedilabs/telemetry/latest/docs/guides/collected-metadata#network) metadata,
  which looks up the public IP address with an external service. Defaults to `true`.
- `git` (Boolean) Whether to collect [`git`](https://registry.terraform.io/providers/tedilabs/telemetry/latest/docs/guides/collected-metadata#git) metadata. Defaults to `true`.
- `github` (Boolean) Whether to collect [`github`](https://registry.terraform.io/providers/tedilabs/telemetry/latest/docs/guides/collected-metadata#github) metadata
  with the GitHub CLI. Defaults to `false`.
- `github_actions` (Boolean) Whether to collect [`github_actions`](https://registry.terraform.io/providers/tedilabs/telemetry/latest/docs/guides/collected-metadata#github_actions) metadata. Defaults to `true`.
- `hcp_terraform` (Boolean) Whether to collect [`hcp_terraform`](https://registry.terraform.io/providers/tedilabs/telemetry/latest/docs/guides/collected-metadata#hcp_terraform) metadata. Defaults to `true`.
- `terraform` (Boolean) Whether to collect [`terraform`](https://registry.terraform.io/providers/tedilabs/telemetry/latest/docs/guides/collected-metadata#terraform) metadata. Defaults to `true`.
- `toolchain` (Boolean) Whether to collect [`toolchain`](https://registry.terraform.io/providers/tedilabs/telemetry/latest/docs/guides/collected-metadata#toolchain) metadata. Defaults to `true`.
- `cache_enabled` (Boolean) Whether to reuse metadata already collected by the same provider process.
  See [Collection Cache](#collection-cache). Defaults to `true`.
- `deduplication_enabled` (Boolean) Whether to skip events that duplicate an event already sent by the same provider process.
  See [Event Deduplication](#event-deduplication). Defaults to `true`.
- `deduplication_keys` (List of String) Paths of the event properties that identify duplicate events, such as `module` or `machine.os`.
  Defaults to `[]`, which compares all event properties.
- `pseudonymized_keys` (List of String) Paths of the event properties to replace with pseudonyms, such as `network.hostname` or `git.remote`.
  See [Pseudonymization](#pseudonymization). Defaults to `[]`.
- `identity_keys` (List of String) Paths of the event properties from which to derive the `distinct_id` of the event, such as `git.remote`.
  See [Distinct ID](#distinct-id). Defaults to `[]`, which sends a random `distinct_id`.

## Return Type

The function returns a `bool` that is always `true`.
The value does not indicate whether the event was sent or delivered,
so the function can be used as a `check` assertion condition that never fails.

## Event Format

Each call that is not skipped sends one `terraform_capture` event.
By default, every event has a new random UUID as its `distinct_id`; see [Distinct ID](#distinct-id).
The event properties contain the enabled metadata groups and the attributes of `extra_data`:

```json
{
  "api_key": "<project token>",
  "event": "terraform_capture",
  "distinct_id": "<random UUID, or a hash of the identity_keys values>",
  "properties": {
    "$process_person_profile": false,
    "$geoip_disable": true,
    "$lib": "terraform-provider-telemetry",
    "$lib_version": "<provider version>",
    "machine": { "os": { "name": "Ubuntu", "version": "24.04" }, "arch": "amd64", "cpu_count": 4, "memory_size": 8192 },
    "module": "example",
    "version": "1.0.0"
  }
}
```

The `$process_person_profile` and `$geoip_disable` properties default to `false` and `true`,
so PostHog neither creates person profiles nor adds GeoIP properties.
The `$lib` and `$lib_version` properties identify this provider and its version as the sending library.
`extra_data` can override all four.
The request also carries the `User-Agent` header `terraform-provider-telemetry/<provider version>`.
See the PostHog [capture API](https://posthog.com/docs/api/capture) for the event format.

### Merging `extra_data`

The attributes of `extra_data` are merged into the event properties, and take precedence over the collected metadata:

* Objects and maps merge recursively. For example, `{ machine = { os = { version = "custom" } } }`
  replaces only `machine.os.version`, and keeps the other collected `machine` properties.
* Other values, including lists and `null`, replace the existing value.
  For example, `{ machine = null }` replaces the whole `machine` group.
* `extra_data` cannot change the `api_key`, `event`, and `distinct_id` fields of the event.
  Attributes with these names become event properties.

## Collected Metadata

Each enabled collector adds a metadata group, named after its option, to the event properties:

| Option | Default | Properties |
| --- | --- | --- |
| `machine` | `true` | `os.name`, `os.version`, `arch`, `cpu_count`, `memory_size` |
| `network` | `true` | `hostname`, `public_ip` |
| `git` | `true` | `name`, `branch`, `commit`, `remote` |
| `github` | `false` | `login`, `id`, `name`, `html_url`, `account_type` |
| `github_actions` | `true` | Workflow, job, run number, repository, actor, ref, and runner details |
| `hcp_terraform` | `true` | Run, workspace, project, and configuration version details |
| `terraform` | `true` | `command_id`, `cli`, `cli_version`, `workspace`, `workspace_source` |
| `toolchain` | `true` | `terraform`, `opentofu`, `git`, `github_cli`, `telemetry_provider` |

Values that are not available are omitted.
See the [Collected Metadata](https://registry.terraform.io/providers/tedilabs/telemetry/latest/docs/guides/collected-metadata) guide for the type, source, and privacy considerations of each property.

<a id="distinct-id"></a>
## Distinct ID

PostHog attributes events to users by their `distinct_id`.
By default, every event has a new random UUID as its `distinct_id`, so each event appears as a different user.
To count something else, such as repositories or machines, set `identity_keys` in `options`
to the paths of the properties that identify it. The `distinct_id` then becomes a hash of their values:

| `identity_keys` | Events that share a `distinct_id` |
| --- | --- |
| `["git.remote"]` | Events from the same Git repository |
| `["hcp_terraform.workspace_id"]` | Events from the same HCP Terraform workspace |
| `["network.hostname"]` | Events from the same machine |
| `["terraform.command_id"]` | Events from the same Terraform command |

* Paths use the syntax of `deduplication_keys`, and select the event properties after merging `extra_data`.
  The selected collectors must be enabled.
* The `distinct_id` is the first 128 bits of the SHA-256 hash of the paths and their values, in hexadecimal.
  The order of the paths does not matter.
* If a selected path is missing, for example when the working directory is not in a Git repository,
  the event has a random UUID as its `distinct_id`.
* The hash reveals nothing that the selected properties do not already contain, but it links the events that share these values.

Events are still sent without person profiles, so PostHog features that require them,
such as person properties, cohorts, and Lifecycle insights, are not available for these events.
To create person profiles, set `"$process_person_profile" = true` in `extra_data`.
PostHog charges more for events with person profiles;
see [Anonymous vs identified events](https://posthog.com/docs/data/anonymous-vs-identified-events) in the PostHog documentation.

<a id="collection-cache"></a>
## Collection Cache

By default, each metadata group is collected once per provider process and reused by later calls.
Set `cache_enabled = false` in `options` to collect fresh metadata for a call.
See the [Caching and Deduplication](https://registry.terraform.io/providers/tedilabs/telemetry/latest/docs/guides/caching-and-deduplication#collection-cache) guide for details.

<a id="event-deduplication"></a>
## Event Deduplication

By default, a call is skipped when the same provider process has already sent an event with identical properties.
Set `deduplication_keys` to compare only the selected properties,
or set `deduplication_enabled = false` to send every event.
See the [Caching and Deduplication](https://registry.terraform.io/providers/tedilabs/telemetry/latest/docs/guides/caching-and-deduplication#event-deduplication) guide for details.

<a id="pseudonymization"></a>
## Pseudonymization

Set `pseudonymized_keys` to replace the values of the selected properties with pseudonyms,
for example `["network.hostname", "network.public_ip", "git.remote"]`.
A pseudonym is the HMAC-SHA256 of the value, keyed by the project token,
truncated to 16 bytes and written as 32 lowercase hexadecimal characters.
Strings are hashed as they are, and other values, including objects and lists, as their JSON encoding.
Null values and paths that are not in the event are left unchanged.

The same value has the same pseudonym in every event sent to the same PostHog project,
so you can still count distinct hosts, repositories, or users without receiving the values.
In a project with a different token, the same value has a different pseudonym.
Pseudonymization applies to the final event properties, including `extra_data`,
before [deduplication](#event-deduplication) and the [distinct ID](#distinct-id), which use the pseudonyms.

~> **Note:** Pseudonyms are not anonymous. Anyone who knows the project token, including everyone who can read a module that contains it and everyone who can read the events, can test guesses of the original values. Values with few possibilities, such as public IPv4 addresses, branch names, or well-known repository URLs, can be recovered by trying them all. To keep a value from being sent at all, disable its collector.

## Error Handling

The function never returns an error or a warning. It skips the capture and returns `true` when:

* `connection` or `options` is null, `connection.host` is not a valid URL, or `connection.project_token` is empty.
* An argument contains unknown values, such as attributes of resources that are not created yet.
  A later evaluation with known values can send the event.
* `options` has an unknown attribute, an attribute of `options` is null or has the wrong type,
  or a path in `deduplication_keys`, `pseudonymized_keys`, or `identity_keys` has an empty segment.
* `extra_data` is not an object or a map.

Terraform still rejects a call with the wrong number of arguments or incompatible argument types before the function runs.

Collection and delivery share a five-second time limit, and each command and HTTP request times out after two seconds.
Requests are not retried, redirects are not followed, and the standard proxy environment variables are honored.

To see why a capture was skipped or whether delivery failed, run Terraform with `TF_LOG_PROVIDER=DEBUG`
(or `TF_LOG=DEBUG`). The function logs the reason of every skip and the result of every delivery at the debug level.
The logs never contain the project token or the event properties.
